# Спецклавиши MX Keys for Business под Linux

Три клавиши, которые без Solaar под Linux бесполезны:

- **F5, Dictation** — голосовой ввод. Нажал и держишь — говоришь.
  Отпустил — текст вставился туда, где курсор. Ей посвящён почти весь документ.
- **F7, Mute Microphone** — выключение микрофона. Одно правило,
  [в конце](#клавиша-mute-microphone-f7).
- **Screen Capture** — снимок экрана. Тоже одно правило,
  [в конце](#клавиша-screen-capture).

## Как устроена диктовка

```
клавиша F5 → Solaar (перехват HID++) → ~/.local/bin/dictate → служба → Whisper → буфер → Ctrl+V
```

| Файл | Роль |
|---|---|
| `~/.local/share/dictate/daemon.py` | служба: держит модель в видеопамяти, пишет звук, распознаёт, вставляет |
| `~/.local/share/dictate/run-daemon.sh` | обёртка: подкладывает CUDA-библиотеки из venv |
| `~/.local/bin/dictate` | клиент, его запускает Solaar: `start`, `stop`, `toggle` |
| `~/.config/systemd/user/dictate.service` | автозапуск при входе в систему |
| `~/.config/solaar/rules.yaml` | правила Solaar: нажатие → start, отпускание → stop, плюс правила для F7 и снимка экрана |
| `~/.local/share/dictate/venv` | окружение с faster-whisper (2,6 ГБ) |
| `~/.local/share/dictate/tray.py` | значок в трее: состояние и выбор микрофона |
| `~/.local/share/icons/hicolor/scalable/status/dictate-*.svg` | четыре состояния значка |
| `~/.config/systemd/user/dictate-tray.service` | автозапуск значка |
| `~/.config/dictate/source` | выбранный микрофон; нет файла или пусто — системный |
| `~/.config/dictate/sounds` | `0` выключает звуковые сигналы |
| `~/.config/dictate/preroll` | `1` включает предзапись; по умолчанию выключена |
| `~/.local/share/dictate/sounds/*.wav` | три сигнала: старт, готово, ошибка |

Перехват клавиш включён в `~/.config/solaar/config.yaml`: у MX Keys в `divert-keys`
ключи `259` (Dictation), `284` (Mute Microphone) и `266` (Screen Capture) стоят в `1`.
Если сбросятся в `0` — клавиши вернутся к заводскому поведению, то есть к бесполезному.

Включать перехват удобнее из окна Solaar. Через командную строку на русской локали
не выйдет: значения выбора локализованы («Перенаправлено»), а Solaar 1.1.19 падает
на не-ASCII аргументе — `TypeError: Unable to marshal str as an array`. Либо правьте
`config.yaml` руками при остановленном Solaar, либо пользуйтесь окном.

## Два режима

**Удержание (сейчас включён).** Правило шлёт `start` на нажатие и `stop` на отпускание.
Паузы в речи запись не обрывают.

**Нажал / нажал ещё раз.** Запись останавливается сама после 1,5 с тишины.
Чтобы перейти, замените `rules.yaml` на одно правило:

```yaml
%YAML 1.3
---
- Key: [Dictation, pressed]
- Execute: [~/.local/bin/dictate, toggle]
...
```

После правки Solaar надо перезапустить.

## Что можно подкрутить

Переменные задаются через `systemctl --user edit dictate.service`:

```ini
[Service]
Environment=DICTATE_LANG=ru
Environment=DICTATE_SILENCE_SEC=1.5
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DICTATE_MODEL` | `large-v3-turbo` | модель Whisper |
| `DICTATE_LANG` | `ru` | язык; пусто — автоопределение |
| `DICTATE_SILENCE_SEC` | `1.5` | сколько тишины = конец фразы (только режим toggle) |
| `DICTATE_MIN_THRESHOLD` | `0.006` | нижняя граница порога громкости |
| `DICTATE_MAX_SEC` | `120` | предохранитель от бесконечной записи |
| `DICTATE_RESTORE_CLIPBOARD` | `1` | возвращать прежнее содержимое буфера |
| `DICTATE_SOURCE` | пусто | закрепить конкретный микрофон; пусто — системный по умолчанию |

## Значок в трее

Показывает состояние (готова / идёт запись / распознаю / служба остановлена)
и даёт выбрать микрофон прямо из меню.

Живость службы определяется по сокету, а не по файлу состояния: файл остаётся
лежать с последним значением и после остановки, поэтому по нему значок показывал бы
«готова» у выключенной службы. У остановленной глиф другой — без волн и с крестиком.

Пункты меню зависят от состояния:

| Служба работает | Служба остановлена |
|---|---|
| Начать / остановить запись | — (неактивно) |
| Перезапустить службу | Запустить службу |
| Остановить службу | — |
| ☐ Не терять начало фразы | ☐ то же самое |
| ☑ Звуковые сигналы | ☑ то же самое |
| ☑ Запускать при входе в систему | ☐ то же самое |

Остановка из меню освобождает видеопамять: модель уходит вместе с процессом
(проверено — около 2,2 ГБ). Обратный запуск занимает примерно пять секунд,
модель берётся из кэша.

**Галочка «Запускать при входе»** — это штатный флаг systemd, то же самое, что
`systemctl --user enable/disable dictate`. Своего файла настроек нет, читать
при входе ничего не надо: systemd сам решает, поднимать службу или нет.

Галочка намеренно **не трогает уже запущенную службу** — она только про следующий
вход. Снять галочку и остановить сейчас — это два разных пункта меню.

Значок (`dictate-tray`) включается отдельно и остаётся в автозапуске всегда.
Поэтому при снятой галочке после входа в систему появится только значок,
а службу можно поднять из его же меню. Выбор пишется в `~/.config/dictate/source`, служба перечитывает его
перед каждой записью — перезапускать ничего не надо.

Значок повторяет глиф с клавиши Logitech: голова, плечи куполом и две волны.
Три состояния лежат в `~/.local/share/icons/hicolor/scalable/status/`:
`dictate-symbolic.svg`, `dictate-recording-symbolic.svg`, `dictate-busy-symbolic.svg`.
Цвет в них `#bebebe` — условный «передний план» для символьных значков, GNOME
подменяет его под тему. Поправили SVG → `systemctl --user restart dictate-tray`.

Рисуется через AyatanaAppIndicator3. В GNOME на Wayland своего трея нет, значки
показывает расширение `ubuntu-appindicators` — если значок пропал, проверьте,
включено ли оно: `gnome-extensions list --enabled | grep appindicator`.

```bash
systemctl --user status dictate-tray     # состояние
systemctl --user restart dictate-tray    # перезапустить
systemctl --user disable --now dictate-tray   # убрать совсем
```

## «Не терять начало фразы» (предзапись)

**По умолчанию выключено.** Включается галочкой в меню значка.

Зачем нужно: `pw-record` отдаёт первый отсчёт примерно через **170 мс** после
запуска (замерено; на первом за сеанс запуске доходило до 560 мс). Пока поток
открывается, микрофон не пишет, и начало фразы теряется.

Как работает: микрофон держится открытым постоянно, последние `DICTATE_PREROLL_SEC`
(0,6 с) лежат в кольцевом буфере в оперативной памяти — старое непрерывно затирается
новым. По нажатию клавиши буфер становится началом записи. Поэтому не теряется ни
задержка открытия, ни слог, сказанный чуть раньше кнопки.

**Цена:** пока включено, в панели GNOME постоянно горит индикатор «микрофон
используется», потому что поток захвата действительно активен. На диск ничего
не пишется и никуда не передаётся, но микрофон занят. Поэтому умолчание —
выключено: такое решение человек принимает сам.

При выключенной галочке микрофон открывается только на время записи и закрывается
через 0,14 с после неё (замерено).

## Уведомления

Все уведомления отправляются с флагом `-e` (transient) и переиспользуют номер
предыдущего через `-r`.

**Зачем.** Без `-e` GNOME складывает каждое уведомление в историю, и после дня
работы экран блокировки оказывается завален десятками «Диктовка» — одна диктовка
шлёт до трёх штук. Подсказки `x-canonical-private-synchronous` для этого мало:
она заменяет только всплывающую плашку, но в список всё равно кладёт.

Если история уже накопилась, старые уведомления убираются кнопкой «Очистить»
в шторке уведомлений — задним числом их не удалить.

## Звуковые сигналы

Три коротких тона: подъём на старте записи, высокий при вставке текста, низкий
при неудаче. Выключаются галочкой в меню значка или файлом `~/.config/dictate/sounds`
со значением `0`. Файлы лежат в `~/.local/share/dictate/sounds/`, сделаны синусом
со сглаженными краями — без фейдов на краях слышен щелчок.

**Почему порог считается скользящим окном.** Сигнал старта звучит уже после того,
как микрофон открыт, и попадает в запись. Первая версия замеряла фон по первым
долям секунды — сигнал задирал его в сорок раз (0,003 → 0,14), и порог становился
непригодным. Теперь фон берётся как 20-й процентиль окна в две секунды: короткий
громкий звук попадает в верхнюю часть распределения и на оценку не влияет. Заодно
это защищает от щелчка мыши, кашля и хлопнувшей двери.

Пока окно не заполнилось, порог держится на нижней границе `DICTATE_MIN_THRESHOLD`.
Ранняя оценка негодная по той же причине, и лучше недооценить порог, чем переоценить:
заниженный порог в худшем случае продлит запись, завышенный — обрежет речь.

## Микрофон

Выбирается из меню значка. Либо, если значок не нужен, по умолчанию берётся тот, что выбран в системе, поэтому обычно править ничего не надо:
**Параметры → Звук → Ввод**. Там же громкость — если распознаёт через раз, поднимите её.

Из командной строки:

```bash
wpctl status                          # список, звёздочка — текущий
wpctl set-default 47                  # переключить
wpctl set-volume @DEFAULT_AUDIO_SOURCE@ 0.9
```

Закрепить микрофон за диктовкой отдельно от системного выбора —
`systemctl --user edit dictate.service`:

```ini
[Service]
Environment=DICTATE_SOURCE=alsa_input.pci-0000_00_1f.3.analog-stereo
```

Имя узла берётся из `pw-cli ls Node` (строки `node.name` с `media.class = "Audio/Source"`).

## Если сломалось

```bash
systemctl --user status dictate
journalctl --user -u dictate -f
```

Проверить по частям:

```bash
dictate start; sleep 3; dictate stop   # в обход клавиши
pgrep -af 'solaar --window=hide'       # жив ли Solaar
grep divert-keys ~/.config/solaar/config.yaml | head -1   # ищите "259: 1", "284: 1", "266: 1"
wpctl get-volume @DEFAULT_AUDIO_SOURCE@                   # состояние микрофона
```

Правила и перехват Solaar читает при запуске, так что после правки
`rules.yaml` или `config.yaml` его надо перезапустить.

## Две грабли, на которые уже наступили

**PyAV.** `faster-whisper` требует `av>=11` без верхней границы, а в av 19 убрали
аргумент `metadata_errors`, который он всё ещё передаёт. Поэтому служба читает WAV
сама и отдаёт модели готовый массив — PyAV в цепочке не участвует. Не «чините»
это обратно на `transcribe(путь)`.

**Текст вставляется через буфер, а не печатается.** uinput шлёт коды клавиш,
а не символы: кириллица зависела бы от текущей раскладки и на английской
превращалась бы в кашу.

## Клавиша Mute Microphone (F7)

К диктовке отношения не имеет и ничего из неё не требует: ни службы, ни модели.

```yaml
- Key: [Mute Microphone, pressed]
- KeyPress: [XF86_AudioMicMute, click]
```

Solaar через свой uinput нажимает `XF86AudioMicMute`, а микрофон глушит
gnome-settings-daemon — со своей плашкой на экране и значком в панели.

Три вещи, которые стоит знать, если будете это разбирать:

**Почему не `Execute` с `wpctl set-mute`.** Так тоже работает, но тогда плашку
и значок пришлось бы изображать самим, а состояние — держать в синхроне
с системой. Чужая работа, которую GNOME и так делает.

**Почему `KeyPress` вообще срабатывает под Wayland.** Solaar переводит имя
клавиши в keycode через раскладку. `XF86_AudioMicMute` разрешается
в X-keycode 198, то есть evdev `KEY_F20` (190), а в раскладке
`pc+us+inet(evdev)` `<FK20>` и есть `XF86AudioMicMute`. Solaar при старте
пишет «rules cannot access modifier keys in Wayland» — это про модификаторы,
простому нажатию не мешает. А вот если бы раскладка была недоступна совсем,
`KeyPress` молча ничего не делал бы: в коде стоит `if gkeymap`.

**Почему это работает при пустой настройке.** В
`org.gnome.settings-daemon.plugins.media-keys` ключ `mic-mute` по умолчанию
`['']`, то есть не назначен. gnome-settings-daemon всё равно реагирует:
для него это аппаратная клавиша, мимо пользовательских привязок.

Проверить, не трогая клавиатуру:

```bash
wpctl get-volume @DEFAULT_AUDIO_SOURCE@   # до
wpctl set-mute  @DEFAULT_AUDIO_SOURCE@ 0  # вернуть как было
```

## Клавиша Screen Capture

На клавиатуре у неё глиф снимка экрана, в Logi Options+ действие называется
`Snipping Tool`. В отличие от двух предыдущих, она не молчит: прошивка шлёт
виндовое Win+Shift+S. В GNOME это сочетание ни к чему не привязано, поэтому
результата нет.

```yaml
- Key: [Screen Capture, pressed]
- KeyPress: [Print, click]
```

`Print` разрешается в X-keycode 107, то есть evdev `KEY_SYSRQ` (99), а GNOME
по умолчанию открывает по нему оверлей снимка — тот самый, с выбором области,
окна или всего экрана.

**Почему `Print`, а не сочетание с буквой.** Если у вас оверлей привязан
к чему-то вроде `<Shift><Control><Alt>i`, велик соблазн эмулировать прямо его.
Не надо: Solaar переводит имя клавиши в keycode через текущую раскладку, и `i`
на русской раскладке не найдётся — `keysym_to_keycode` вернёт `None`, Solaar
напишет в лог `key symbol not currently available` и ничего не сделает.
Клавиша работала бы только на латинице. `Print` от раскладки не зависит.

**Проверьте привязку.** Правило работает только если оверлей висит на `Print`.
Так в GNOME по умолчанию, но привязку можно потерять — например, её забирают
себе программы удалённого доступа:

```bash
gsettings get org.gnome.shell.keybindings show-screenshot-ui   # ждём 'Print' в списке
```

Если `Print` там нет — добавьте, не выбрасывая того, что есть:

```bash
gsettings set org.gnome.shell.keybindings show-screenshot-ui \
  "$(gsettings get org.gnome.shell.keybindings show-screenshot-ui | sed "s/]$/, 'Print']/")"
```

Откатить всё — `gsettings reset org.gnome.shell.keybindings show-screenshot-ui`.

**Тупик, в который не стоит ходить.** У `org.gnome.Shell.Screenshot` есть
метод `InteractiveScreenshot`, который открыл бы оверлей без эмуляции клавиш
и без зависимости от привязок. Он закрыт для обычных программ:
`GDBus.Error:org.freedesktop.DBus.Error.AccessDenied: InteractiveScreenshot
is not allowed`. Это интерфейс для портала, не для нас.

**Проверить, не трогая клавиатуру:**

```bash
gsettings get org.gnome.shell.keybindings screenshot   # обычно '<Shift>Print'
```

Это сочетание сохраняет снимок всего экрана в файл, без оверлея — удобно,
чтобы убедиться, что GNOME вообще получает `Print` от синтетического
устройства ввода: если файл в папке снимков появился, цепочка работает.
